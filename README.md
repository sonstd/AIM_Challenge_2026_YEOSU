# 여수 여행지 추천 서비스 (AIM Challenge 2026 예선)

여행 조건 2문항 + 성향 4문항으로 사용자의 여행 유형(16종)을 판정하고,
그 좌표에 맞는 여수 관광지 BEST 5를 추천 이유·매칭도와 함께 보여주는 Next.js 앱입니다.
백엔드 DB 없이 프로젝트 내부 정적 데이터만 사용합니다.

## 실행

`npm run dev` 하나로 **두 서버**가 뜹니다.

| 포트 | 무엇 |
| --- | --- |
| 3000 | 전시용 화면 + 추천 API (`Next`) |
| 5000 | 평가용 조회 API (`/current_region`) |



Node.js 20.9 이상이 필요합니다.

```bash
npm install
npm run build
npm run start
```

http://localhost:3000 에서 확인합니다. 개발 모드는 `npm run dev`입니다.

## 평가용 조회 API — `GET :5000/current_region`

```
GET http://{HOST}:5000/current_region?region_id=YEOSU
```

| 항목 | 값 |
| --- | --- |
| Method | GET |
| Port | 5000 (`REGION_API_PORT` 로 변경 가능) |
| Bind | **0.0.0.0** — 바깥 IP 로 들어오므로 로컬호스트만 열면 안 됩니다 |
| 응답 | JSON / UTF-8 / 200 OK |

- 돌려주는 건 **가장 최근에 `/api/recommend` 가 만든 응답 본문 그대로**입니다.
  여기서 추천을 새로 만들지 않습니다.
- 추천이 생성될 때마다 `data/recommendations/{region_id}.json` 에 같은 내용이 저장되고,
  조회 API 는 그 파일을 **글자 그대로** 내보냅니다. 그래서
  `제출 JSON == 저장 파일 == 조회 API 응답` 이 항상 같습니다(규칙 1-5).
- 아직 한 번도 추천을 만들지 않았으면 404 입니다. 화면에서 한 번 돌리거나
  `curl -X POST localhost:3000/api/recommend -H 'Content-Type: application/json' -d @request.example.json`
  로 만들어 두면 됩니다.
- `region_id` 누락 400 / 다른 경로 404 / GET 외 405.
- 조회 API 만 따로 띄우려면 `npm run region`, Next 만 띄우려면 `npm run dev:web`.

## API 키 설정

Agent 호출은 **서버사이드에서만** 일어납니다.

```bash
# .env.local
GEMINI_API_KEY=발급받은_키
```

키가 없거나 네트워크가 막혀 Agent에 **닿지 못하면**, 서버는 evidence_text_1~3을
그대로 조립한 결정적 대체 응답을 돌려주고 응답 헤더에
`X-Recommend-Source: fallback`을 붙입니다. 정상 경로는 `agent`입니다.

## 화면 흐름

```
시작 → 여행 조건 2문항 → 여행 성향 4문항 → 성향 결과 → 맞춤 추천 BEST 5 (대화형)
                                                              └ 미리 여행 체험 → 대기 게임 → 영상
```

- 조건 2문항(동반·기간)은 **X/Y 점수에 전혀 반영되지 않습니다.**
  후보 감점과 Agent 어조 조정에만 씁니다.
- 성향 4문항은 `X1 → Y1 → X2 → Y2` 순서로 노출됩니다.
- 4문항을 모두 답해야 결과 화면으로 넘어갑니다(서버에서도 다시 검사합니다).
- 선택지를 누르면 **그대로 다음 문항으로 넘어갑니다**(조건·성향 모두). 전시장에서
  터치 수를 줄이기 위한 것이고, 고친 답은 "← 이전 질문"으로 되돌립니다.

> 문항이 많아 지루하다는 피드백을 받아 조건 4문항 + 성향 8문항에서 줄였습니다.
> 뺀 문항(경비·이동수단, X3·Y3·X4·Y4)은 git 이력에 남아 있습니다.

## 성향 점수

각 문항은 4단계로 답하고, 값은 화면에 노출하지 않습니다.

| 응답 | 값 |
| --- | --- |
| A가 훨씬 좋아요 | −5 |
| A가 조금 더 좋아요 | −2.5 |
| B가 조금 더 좋아요 | +2.5 |
| B가 훨씬 좋아요 | +5 |

```
X = X1 + X2     (−10 ≤ X ≤ 10)  자연·힐링 ↔ 액티비티·체험
Y = Y1 + Y2     (−10 ≤ Y ≤ 10)  한적·로컬 ↔ 핫플·데이트
```

축당 문항이 4개에서 2개로 줄어든 만큼 **응답 값을 두 배로 키웠습니다.**
X/Y 범위(−10~10)와 16유형 구간, `place-axis.json`의 장소 좌표를 그대로 쓰기 위해서입니다.

구간(각 구간은 왼쪽 경계 포함): `−10~−5` → 1, `−5~0` → 2, `0~5` → 3, `5~10` → 4.
`typeId`는 `X{1-4}Y{1-4}` 형식입니다.

성향 강도: `<2.5` 중립에 가까움 / `<5` 약한 선호 / `<7.5` 뚜렷한 선호 / `≤10` 매우 강한 선호.

> **16개 유형 이름은 아직 TEMP입니다.** `src/config/travel-types.js`의
> `name`/`description`/`keywords`만 교체하면 되고, 판정 로직과 UI는 손댈 필요가 없습니다.

## 추천 파이프라인

```
POST /api/recommend
{
  "conditions": { "companion": "가족", "duration": "당일치기" },
  "answers": { "X1": -5, "Y1": -2.5, "X2": -2.5, "Y2": -5 }
}

① 스코어링   매칭도(0~100) + 동반 자동 태그 가산 − 조건 감점
② 후보 압축   상위 10곳 (최소 7곳 보장), 배타 그룹은 점수 높은 쪽만
③ Agent      후보의 evidence_text_1~5 기반으로 정확히 5곳 선정, 이유는 3문장
④ 검증        화이트리스트 / 중복 / 개수(정확히 5) / 문장수(2~5) / 과한 사투리
             → 실패 시 최대 3회 재호출
             인용부호·종결 어미 중복은 경고 로그 (CLAUDE.md §3 [6])
⑤ 응답 조립   getPlaceById()로 place_name·image_prompt·images 결합
```

**X/Y 좌표는 클라이언트가 보낸 값을 믿지 않고 성향 문항 응답에서 서버가 다시 계산합니다.**

문장 수는 `.` `!` `?` 로만 셉니다. **숫자 사이의 점(1.5km)은 문장 구분자가 아니므로**
평가 기준과 같게 한 문장으로 셉니다(`splitSentences`). 소수점 수치를 막던 규칙은
그래서 없앴습니다.

**매칭도**는 사용자 좌표와 장소 좌표의 거리를 최대 거리(√800)로 정규화한 값입니다.
조건 감점을 섞지 않아서, "성향이 얼마나 맞는가"만 나타냅니다.

조건 감점은 **후보 선정과 Agent의 5곳 선택까지만** 영향을 줍니다. 최종 응답의
`recommendations` 배열은 매칭도 내림차순으로 정렬해서 내보냅니다. 카드에 순위 배지와
매칭도가 함께 붙기 때문에, 둘의 순서가 어긋나면 버그처럼 보이기 때문입니다.

`avoid_tags`는 하드 필터가 아니라 소프트 감점입니다. 동반 유형(`AVOID_PENALTIES`)과
기간(`DURATION_PENALTIES`) 감점표를 합산합니다.
`가족`이면 `아이와함께`, `연인`이면 `로맨틱·커플` 태그를 가진 장소에 가산점을 주고
`matched_tags`에도 포함시킵니다.

**중립 축 보정**: 응답값이 ±2.5 / ±5 두 개의 합이라 축 합계가 구간 경계에 자주 떨어집니다.
한 축이 경계(−5, 0, +5)에 정확히 걸릴 확률이 50%, 적어도 한 축이 경계일
확률이 75%입니다. 그래서 `|점수| < 2.5`인 축은 중립으로 보고 **양쪽 성향 태그를 모두**
매칭 대상으로 삼습니다. 그러지 않으면 합계가 정확히 0인 사용자에게 "0은 음수가 아니다"는
이유만으로 반대쪽 태그가 통째로 잘려 나갑니다. 결과 화면에서도 이 경우 유형 이름보다
"중간에 가까움"을 먼저 보여 줍니다.

## 소리 — 배경음악과 음성 안내

| 화면 | 소리 |
| --- | --- |
| 인트로 | `public/mp3/start.mp3` 반복 |
| 대기 게임 | `public/mp3/game.mp3` 반복 |
| 설문 | 질문을 읽어 줍니다(묻는 사람이 돌아본 뒤) |
| 추천 결과 | 말풍선이 뜰 때 추천 근거를 읽어 줍니다 |

- 배경음악은 `src/lib/audio.js`, 음성은 `src/lib/speech.js` 가 맡습니다.
  화면 코드는 `playLoop` / `stopLoop` / `speak` / `cancelSpeech` 만 씁니다.
- **음성은 Gemini TTS** 로 만듭니다(`gemini-3.8-flash-tts`, 목소리 `Sulafat`).
  서버 라우트 `/api/speech` 가 WAV 를 만들어 돌려주고, 키는 서버에만 둡니다.
  - **한 문장에 5초쯤 걸립니다.** 그래서 필요해지기 전에 미리 받아 둡니다
    (`prime`) — 질문 6개는 앱이 뜨자마자, 추천 근거는 결과 화면에 들어서자마자.
  - 같은 글은 `data/tts/` 에 저장해 두고 다시 만들지 않습니다. 질문 6개는 사실상
    한 번만 만듭니다(두 번째부터 0.1초).
  - **사람마다 목소리가 다릅니다.** 남자 출연자는 남자 목소리, 여자 출연자는 여자
    목소리를 씁니다(`src/config/intro.js` 의 `voice`).

    | | 출연자 | 목소리 |
    | --- | --- | --- |
    | 남 | 박만수 / 정상길 / 한기철 | Charon(차분) / Puck(들뜬) / Umbriel(느긋) |
    | 여 | 김말순 / 문지혜 / 백설희 | Sulafat(따뜻) / Callirrhoe(편안) / Vindemiatrix(부드러움) |

    추천 결과 대화는 프로필이 박만수라 **Charon(남)** 으로 읽습니다
    (`src/config/chat-questions.js` 의 `NARRATOR_VOICE`).
    쓸 수 있는 이름은 `src/lib/tts.js` 의 `TTS_VOICES` 에 있고, 목록에 없는 값이
    오면 기본 목소리로 떨어집니다.
  - **다 읽은 뒤에 다음 말풍선이 뜹니다.** 읽는 도중에 자동으로 넘어가 말이 끊기던
    문제를 막기 위해, 다음 질문 칩을 낭독이 끝난 뒤에 띄웁니다.
  - 소리를 꺼 두면 읽지 않되, **읽었을 만큼 기다렸다가** 다음으로 넘어갑니다
    (대화 속도가 들쭉날쭉해지지 않게).
  - 서버가 막히면 **브라우저 내장 TTS 로 대신 읽습니다**(소리가 아예 없는 것보다 낫습니다).
- 말소리가 나오는 동안 배경음악이 자동으로 낮아집니다.
- **브라우저는 화면을 한 번 건드리기 전까지 소리를 막습니다.** 막히면 첫 터치를
  기다렸다가 다시 틉니다. 처음부터 소리가 나게 하려면 크롬을
  `--autoplay-policy=no-user-gesture-required` 로 띄우세요.
- 무대 오른쪽 위 작은 버튼으로 소리를 끌 수 있습니다.

## 무대 — 모든 화면이 한 무대 안에서

인트로의 16:9 무대를 앱 전체로 올렸습니다. 바깥은 어두운 매트, 안쪽이 무대이고,
화면이 바뀌어도 같은 무대라 한 편의 방송처럼 이어집니다.

- **무대 안은 1280×720 고정 좌표계**입니다(`--stage-w` / `--stage-h`). 화면 크기에
  맞춰 통째로 축소하므로 해상도가 달라도 구성이 똑같습니다. 전시 기준인
  1280×800 에서 배율이 1 이고, 1024×768 에서는 0.78 입니다.
  CSS 로는 길이를 길이로 나눌 수 없어 배율만 `src/components/Stage.js` 가 계산합니다.
- 높이를 쓰는 화면은 `100dvh` 가 아니라 `var(--stage-h)` 를 기준으로 잡습니다.
- 인트로는 축소 대상이 아닙니다. 글자 크기가 `cqw`(무대 폭 기준)라 이미 무대에
  비례합니다.
- **장면이 바뀔 때 번쩍입니다**(`.stage-flash`). 인트로의 플래시를 그대로 씁니다.
- 화면 제목은 인트로 타이틀과 같은 **무지개 레트로 글자**입니다
  (`RetroText` / `src/lib/retro-text.js`). 본문에는 쓰지 않습니다.
- 주요 버튼은 인트로 TEST 버튼과 같은 모양입니다(`.retro-cta`).

## 화면 디자인 — 토박이 컨셉

시작부터 결과까지를 **토박이가 묻고 답하는 하나의 대화**로 묶었습니다.

| 토큰 | 용도 |
| --- | --- |
| `--sea` | 주조색(여수 바다 청록). `--accent` 계열이 여기서 파생합니다 |
| `--camellia` | 강조색(동백). **버튼·선택 상태·진행률에만** 씁니다 |
| `--paper` | 바탕. **인트로 무대와 같은 하늘 계열**의 아주 밝은 톤 + 미세한 결 |
| `--ink` | 본문 텍스트. 순검정 대신 짙은 갈회색 |

- 본문·선택지·질문은 **Pretendard(고딕)**. 손글씨풍(`Ria`)은 시작 화면 제목과
  결과 화면 유형 이름에만 씁니다.
- 질문 문구는 `src/config/survey-copy.js`, 안내 캐릭터 그림은
  `public/images/characters/local-guide.svg` 입니다(경로만 유지하면 교체 자유).
- 전시 운영: 선택하면 바로 다음 문항으로 넘어가고, **어느 화면이든 60초간
  조작이 없으면 시작 화면으로 되돌아갑니다**(`IDLE_RESET_MS`).

## 결과 화면 — 메신저 대화형

현장 전시(태블릿)용 화면입니다. 카드로 설명문을 늘어놓으면 읽지 않고 넘어가므로,
여수 토박이에게 물어보는 대화로 풀어 체류 시간을 늘립니다.

```
[헤더] 유형 + 장소명 + 매칭도
[대화] 1순위 — 질문 칩 탭 → 말풍선 (문장 하나당 말풍선 하나)
[카드] 나머지 추천 — 탭하면 그 장소 대화로 전환
```

- **문장 → 질문 매핑** (`src/lib/chat-script.js`): 2문장 → Q1·Q3, 3문장 → Q1~Q3,
  4문장 이상 → 남는 문장을 마지막 답변에 말풍선으로 더 붙입니다.
- **문장 분리는 `src/lib/sentences.js` 한 곳**에서만 합니다. 검증 레이어와 같은 규칙이고,
  화면용 분리는 종결 부호를 떼지 않아 **화면 문장이 API 원문과 글자 단위로 같습니다.**
- 질문 문구·화자 이름·타이밍은 `src/config/chat-questions.js` 에 모아 두었습니다.
- **대화와 카드를 나란히** 둡니다. 무대가 16:9 라 가로가 넓고 세로가 짧아서,
  세로로 쌓으면 둘 다 답답해집니다. 대화가 무대 높이를 거의 다 씁니다(431px).
- **사진은 버튼으로** 보여 줍니다. 말풍선으로 바로 깔면 대화 영역을 많이 차지하고
  좁은 틀에 맞추느라 잘립니다. `사진 보기` 를 누르면 무대 가득 원본 비율로 띄웁니다.
- **자동 진행**: 칩을 8초간 누르지 않으면 첫 칩을 대신 누릅니다(전시장에서 멈춘 화면 방지).
- **유휴 복귀**: 시작 화면을 뺀 **모든 화면**에서 60초간 조작이 없으면 처음으로 돌아갑니다.
  타이머는 `Wizard` 한 곳에만 있습니다(화면마다 따로 재지 않습니다).

## 미리 여행 체험 — 선택 → 대기 게임 → 영상

결과 화면의 **미리 여행 체험해보기** 버튼에서 시작합니다.

```
선택(장소 1곳 + 캐릭터 1명) → [시작하기] → 영상 생성 요청 → 대기 게임 → 영상
```

- **영상 생성은 `src/lib/video.js` 의 `requestVideo` / `pollVideo` / `isVideoExpired`
  세 함수로만** 주고받습니다. 화면에는 대기 시간을 재는 타이머가 없습니다.
  - 실제 호출은 **서버 라우트 `/api/video`** 가 합니다. 키가 브라우저로 나가면 안 되므로
    화면은 Comfy Cloud 를 직접 부르지 않습니다.
  - `VIDEO_TIMEOUT_MS`(300초)를 넘기면 게임을 멈추고 안내 화면으로 보냅니다.
- `requestVideo` 는 **[시작하기]를 누른 직후** 호출합니다. 게임이 끝난 뒤에 요청하면
  관람객이 또 기다리게 됩니다.
- 캐릭터는 **6종**(아저씨 3 + 아줌마 3, `src/config/characters.js`)입니다.
  그림(`public/images/characters/avatar_*.svg`)은 **영상 레퍼런스와 같은 파일**을 씁니다.
  UI용 일러스트를 따로 두면 영상에 다른 사람이 나온 것처럼 보입니다.
  `id`(`MALE_1`…`FEMALE_3`)는 영상 요청에 그대로 실려 나가므로 파일명과 맞춰 두었습니다.

### 대기 게임 — 틀린 그림 찾기

새 이미지를 만들지 않습니다. **추천 장소 사진 위에 SVG 요소를 올려** 두 장을 만들고,
오른쪽 그림에서 일부를 제거·좌우 반전·색 변경합니다. 정답 좌표를 코드가 들고 있으므로
판정이 정확하고, 배치를 무작위로 돌리면 라운드가 무한히 생성됩니다.

| 상수 (`src/lib/spot-game.js`) | 값 | 뜻 |
| --- | --- | --- |
| `ROUND_DURATION_MS` | 90초 | 라운드 제한 시간. 지나면 다음 라운드 |
| `DIFF_COUNT` | 4 | 한 라운드의 틀린 곳. 다 찾으면 즉시 종료 |
| `HINT_AFTER_MS` | 30초 | 힌트 버튼이 열리는 시점(라운드당 1회) |
| `HIT_RADIUS_PX` | 40 | 정답 판정 반경 |

- 두 그림은 **세로로** 쌓습니다. 나란히 두면 태블릿에서 각 그림이 너무 작아집니다.
- 오답은 점수를 깎지 않고 **그림을 흔듭니다.** 벌칙이 세면 소극적으로 변해 시간이 안 갑니다.
- 라운드마다 다른 추천 장소를 쓰고, 끝날 때마다 그 장소를 한 줄로 소개합니다
  (대기 시간을 관광지 노출 시간으로 바꾸는 장치입니다).
- 좌우 반전은 **한 라운드에 한 개까지만** 씁니다. 제거·색 변경보다 눈에 덜 띕니다.

### 영상이 도착하면

라운드 중간이어도 중단합니다. 화면을 즉시 갈아치우지 않고 세 단계로 넘깁니다.

```
토스트 "영상 다 나왔어라우!" (게임은 아직 조작 가능)
  → 2초 뒤 카운트다운 3초 + 찾은 개수 한 줄 + [지금 보러 가기]
  → 영상 화면
```

영상 화면에서 생성된 mp4 를 음소거·반복 재생합니다(전시장이라 소리는 끕니다).

### 마지막 — 오늘의 운세

영상을 다 본 뒤 **오늘 운세 봐 주까라** 를 누르면 **오늘의 여수 운세 뽑기** 로 넘어갑니다.
같이 다녀온 사람이 뒷면이 같은 카드 넉 장을 내밀고, 하나를 고르면 운세·먹거리·가 볼 곳을
사투리로 알려 줍니다(그 사람 목소리로 읽어 줍니다).

- 네 장은 **뒷면이 모두 같습니다.** 무엇이 나올지는 **카드를 누른 순간**에 정해집니다
  (카드마다 결과를 미리 붙여 두면 고르는 의미가 없습니다).
- 장 수는 `FORTUNE_CARDS` 로 바꿉니다.

- 글은 `src/config/fortune.js` 에 있습니다 — 운세 4등급 17문장, 여수 먹거리 10가지.
  **LLM 으로 매번 새로 짓지 않습니다.** 전시장에서는 즉시 떠야 하고, 글이 고정이라야
  음성이 캐시에 남아 두 번째 관람객부터 기다림이 없습니다.
- 등급은 가중 추첨입니다(좋은 쪽이 더 자주 나옵니다).
- **가 볼 곳은 그 관람객이 추천받은 5곳 중에서** 고릅니다. 영상으로 이미 본 곳은 빼서
  마지막에 한 군데를 더 얹어 주는 모양이 됩니다.
- 무작위는 버튼을 누른 순간에 한 번만 돌립니다(화면을 다시 그려도 결과가 안 바뀝니다).

### 영상 생성 — Comfy Cloud (LTX 2.3)

`src/lib/comfy.js` **(서버 전용)** 이 Comfy Cloud 와 주고받습니다.

```
① 레퍼런스 시트 업로드   POST /api/upload/image
② 워크플로에 시트·프롬프트 꽂기
③ 실행 요청             POST /api/prompt      → prompt_id
④ 상태 조회             GET  /api/jobs/{id}
⑤ 결과 주소             GET  /api/view?...    → 302 서명 URL
```

- 환경변수: `COMFY_BASE_URL`, `COMFYUI_API_KEY` (`.env.local`, 서버에서만 읽습니다).
- **워크플로는 API 포맷으로 미리 펼쳐 둡니다.** 원본 UI 그래프(`src/data/workflow_vod.json`)는
  서브그래프가 들어 있어 그대로 보낼 수 없습니다. 워크플로를 새로 받으면 한 번 돌려 주세요.

  ```bash
  node scripts/build-workflow-api.mjs      # → src/data/workflow.api.json
  ```

  입력 이름은 서버의 `/api/object_info` 로 검증합니다. 동적 콤보의 하위 입력은
  `resize_type.shorter_size` 처럼 **점이 들어간 이름 그대로** 보내야 합니다.
- 요청마다 바뀌는 건 두 군데뿐입니다 — `LoadImage`(레퍼런스 시트)와
  긍정 `CLIPTextEncode`(프롬프트). 노드 id 는 `src/lib/comfy.js` 의 `NODE` 에 있고,
  class_type 이 다르면 바로 에러를 냅니다.
- 입력 자료는 **장소 id + 캐릭터 id** 로 찾습니다 (`MALE_2` → `male_02`).

  | 종류 | 경로 |
  | --- | --- |
  | 레퍼런스 시트 | `public/images/reference_sheets/{장소id}/{캐릭터}.png` |
  | 생성 프롬프트 | `public/vod_gen/{장소id}/{캐릭터}/prompt.txt` |
  | 시드 | `public/vod_gen/{장소id}/{캐릭터}/seed.json` |

  **전부 서버 안의 파일만 씁니다**(외부에서 받아 오지 않습니다). 프롬프트가 없으면
  `PROMPT_EMPTY` 로 끊습니다. 프롬프트 앞에 붙은 `male_01` / `Generated video:` 같은
  머리말 줄은 떼어 내고 보냅니다.
- **시드**는 `{"RandomNoise": …, "Stage2Noise": …}` 두 개이고, 워크플로의
  `RandomNoise`·`Stage2 Noise (fixed)` 노드에 꽂힙니다. 파일이 없거나 비어 있으면
  워크플로에 적힌 기본 시드를 그대로 씁니다(생성은 그대로 됩니다).
  같은 장소·캐릭터는 프롬프트와 시드가 고정이라 **영상도 매번 같습니다.**
- 장소·캐릭터 id 는 **기준 데이터와 대조한 뒤에만** 경로에 끼웁니다(경로 탈출 방지).
- 배정된 머신에 모델이 아직 없으면 제출 직후 검증에서 떨어집니다. 검증 실패는 GPU 를
  쓰지 않으므로 **최대 3번까지 다시 보냅니다**(`MAX_SUBMIT_ATTEMPTS`).
- **클라우드의 모델 목록은 말없이 바뀝니다.** 워크플로가 부르는 이름이 아직 있는지
  아래 명령으로 미리 확인하세요(없으면 영상 생성이 통째로 막힙니다).

  ```bash
  node scripts/check-workflow-models.mjs
  ```
- 같은 장소·캐릭터는 클라우드가 결과를 그대로 재사용합니다(내용 주소 저장).
  처음 생성은 30초 안팎, 두 번째부터는 몇 초면 끝납니다.

## 추천 이유 어투

추천 이유는 **전남 사투리가 섞인 친근한 구어체**로 생성합니다. 여수를 잘 아는 동네
사람이 여행객에게 일러 주는 말투이고, 정량평가(근거성)보다 정성평가의 "가고 싶게
만드는 느낌"을 노린 선택입니다.

- 어미 중심으로 바꿉니다: `~입니다 → ~이지라 / ~이랑께요`, `~좋습니다 → ~딱 좋아라우`
- **의미와 정보는 evidence 원문 그대로 둡니다.** 어투를 바꾸면서 `아름다운`, `정겨운`
  같은 평가어를 새로 넣는 것은 금지입니다(Agent 규칙 10, 10-1).
- `keep_terms`(예술 섬·아쿠아리움·버스킹 등 고유 표현)는 사투리로 바꾸지 않습니다.
- 세 문장이 모두 같은 어미로 끝나지 않게 합니다.
- 코드 검증: 과한 사투리(허벌나게·거시기·워메·그라제·아따)는 **재호출**,
  종결 어미가 모두 같으면 **경고 로그**를 남깁니다(`src/lib/validate.js`).

## 응답 형식

```json
{
  "region_id": "YEOSU",
  "recommendations": [
    {
      "place_id": "YEOSU_008",
      "place_name": "무술목해변",
      "recommend_reason": "...",
      "matched_tags": ["자연·힐링"],
      "image_prompt": "...",
      "images": ["/images/places/YEOSU_008_01.png", "..."]
    }
  ]
}
```

본문 필드는 CLAUDE.md §5 제출 규격과 **정확히 일치**합니다(누락·초과 없음).
제출용 JSON이 필요하면 API를 호출해 응답을 그대로 저장하면 됩니다 — 손으로 고치지 않습니다
(규칙 1-5: 제출 JSON과 REST API 결과가 일치해야 함).

```bash
curl -s -X POST http://localhost:3000/api/recommend -H "Content-Type: application/json" -d @request.json -o 02_지역추천지.json
```

**화면에 쓰는 매칭도는 본문이 아니라 응답 헤더로 내려갑니다.**

```
X-Match-Scores: {"YEOSU_005":92,"YEOSU_019":90,"YEOSU_007":89}
X-Recommend-Source: agent | fallback
```

헤더는 저장되는 JSON에 섞이지 않으므로, 위 curl 결과가 그대로 제출물이 됩니다.
클라이언트는 같은 출처라 이 헤더를 그대로 읽을 수 있습니다.
